# Build plan

1. **Data boundary — implemented:** use `scripts/sync-github.mjs` to curate public, non-fork, non-archived repositories. Never ship a token or private metadata. Keep the generated JSON as a fallback when GitHub is unavailable. Gate: generated snapshot validation and source review.
2. **Content — partially implemented:** use repository descriptions and reviewed README summaries; avoid invented company results, architecture, releases, and deployments. Gate: every public claim has an identified public source or is explicitly framed as a concept. The remaining legacy body copy has not cleared this gate.
3. **Experience — partially implemented:** keep the scene engine and current routes. Add dedicated public-work, project-detail, engineering, and lab layouts. Connect the homepage to real work. Gate: all preserved routes resolve and new surfaces work at mobile and desktop widths. More project-specific storytelling remains.
4. **Discovery — implemented for routes and repositories:** provide filtering, search, keyboard command access, and contextual navigation with accessible states. Gate: keyboard interaction and empty-result checks. Full approved body-text search remains future work.
5. **Quality — implemented for this pass:** run lint, build, scene smoke, browser route/overflow checks, keyboard and reduced-motion checks, and review screenshots at mobile and desktop widths. Gate: no page errors, broken links, or overflow across the route/viewport sweep.
6. **Legacy editorial and component expansion — pending:** verify private/concept pages, replace repeated block composition with evidence-led sections, and build the larger component system. Gate: route-by-route content approval and component reuse demonstrated by actual page needs.
7. **Publishing and performance — pending:** validate preview deployments, route metadata in non-JavaScript crawlers, real-device performance, and screen-reader behavior. Gate: documented outcomes and fixes before declaring full production readiness.

Architecture rule: generated data is read-only presentation input. Browser code never calls an authenticated GitHub API. Components render explicit project records; route pages compose them. The script owns the external shape and privacy boundary.
